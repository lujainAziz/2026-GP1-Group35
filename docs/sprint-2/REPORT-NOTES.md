# Sprint 2 — Report Notes (evidence → report sections)

Maps the Sprint 2 work and evidence to the report sections. Paths are relative to the repo root;
evidence files live under `docs/sprint-2/evidence/`. Status as of 2026-11-02.

## Section 4 — Design and implementation
- **Scope and requirements:** `README.md` → *Requirements tracking* (single PBI-13/PBI-14 table).
- **Suricata Configuration (detection):** `README.md` → *Suricata Configuration*; config
  `appliance/suricata/assas.yaml` (generated by `gen_assas_yaml.py`); service
  `appliance/systemd/assas-suricata.service`; rotation `appliance/suricata/rotate-eve.sh` +
  `assas-suricata-rotate.{service,timer}` and `appliance/suricata/assas-suricata.logrotate`.
  Decisions: IDS/af-packet on `eth1` (never inline); eve limited to alert+stats, no payload/packet;
  rename+SIGHUP rotation with ingester-owned retention (no logrotate on eve.json).
- **Threat Alert Ingestion:** `appliance/alerts.py`, `appliance/systemd/assas-alerts.service`;
  tables `alerts` + `alert_ingest_state`. Decisions: severity from rule priority; device linking
  (one/both→source/neither); dedup window (default 300 s); resume-safe checkpoint in the same
  transaction; reaper deletes only fully-consumed rotated files.
- **Alert API:** `appliance/api.py` (`GET /alerts`, `/alerts/{id}`, `/devices/{mac}/alerts`), reusing
  the existing `require_auth`; response matches the mobile `SecurityAlert` contract (lowercase
  `kind`/`state`/`severity`).
- **Mobile Alert Screens:** `app/mobile` + `app/packages/assas_core`; `FeatureRelease.alerts=true`
  with later-sprint surfaces gated off (`alertsHome`, `alertSeverityBadges`, `alertDisplay`,
  `alertExplanations`, `alertManagement`, `risk`).

## Section 6 — Achievements, limitations, and future work
- **Achievements:** signature-based IDS live on the appliance (ET Open), threat alerts ingested and
  served through an authenticated API, mobile alert screens, additive-only changes with Sprint 1
  suites still green.
- **Limitations / outstanding:**
  - Memory target not validly judged — a representative run without the co-resident dev agent is
    required (procedure in `EVALUATION.md §4`).
  - Detection evaluation pending dataset approval/download and the mirrored-port replay.
  - Mobile **visual review** (three screens) pending capture on a dev machine
    (`evidence/ui/README.md`).
  - ET Open has partial attack coverage by design; detection results will record detected vs
    undetected as observed.
- **Deferred to later sprints (intentionally hidden behind flags):** anomaly detection, network
  risk, alert explanations, alert state management (Reviewed/Resolved), dashboard alert summary,
  device-list severity badges, display alert count.
